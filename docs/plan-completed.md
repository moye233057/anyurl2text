### 今天要交代的事

0g. **统一转换与仓内第三方服务**  
   双路 `/extract`·`/understand` 并成 `POST /convert`（`ocr` / `asr` / `llm` 默认关）。OCR/ASR 进程落在仓库根 `services/{ocr,asr}/<实现>/`，权重在各实现自己的 `models/`（不进 git）；`backend/extensions/` 只留出口客户端。`start.py` 可按条件拉起默认两套。清单迁入 [TODO.md](./TODO.md)，根目录 `TODO.md` 已删。

今天没有啃访问控制、许可证这类要拍板的大项，而是把**已经想清楚、改动面小、立刻能提升稳妥程度**的事做完：
0. **对外部署边界写清**  
   不在仓里做 Dockerfile / systemd / 生产默认多 worker。RUNBOOK 写明：生产环境变量由运维自定，本服务只认已有开关（如关 `RELOAD`、自管 workers、`vite build` + 反代）。决策记入 ADR-0012；原「进程模型」待办结案。

0b. **长音轨先探时长再抽**  
   视频/容器音频抽 wav 前先探时长；已超转写上限（默认 600 秒）则不抽完整音轨；仍抽取时带 ffmpeg `-t` 封顶。超限仍跳过转写并写进 `limits_hit`，不静默截断送 ASR。

0c. **下载钉 IP + PDF/图片预算**  
   下载解析一次后按 IP 建连（关 DNS 二次解析时间窗），解析失败即拒，禁止 https→http。PDF 最多 200 页、单页渲染像素封顶；读图宽×高超预算拒绝；长图 OCR 最多 40 片。命中都进 `limits_hit`。

0d. **请求日志可串起来**  
   每条 JSON 日志带 `request_id`；响应头 `X-Request-ID`；access 行含 method/path/status/耗时；stdout 之外落到 `backend/data/logs/` 并轮转；打 URL 时去掉 query。

0e. **出站客户端复用**  
   DeepSeek 的 OpenAI 客户端与 OCR/ASR 的 httpx 在进程内共用；每单仍自带用量账本。LLM 出口另有很宽的并发闸（默认 64），只给极大流量当安全网，本机自用几乎碰不到。

0f. **第三方成本控制**  
   单价表与记账从 `usage.py` / `settings` 迁入 `models/deepseek.py`，按官方 Flash 价再核对。可用开关打开单请求费用或 token 上限；本机 OCR/ASR 不进闸。未做请求缓存/去重。

1. **读文件头不再整文件进内存**  
   代码里其实早已改对；今天核对后结案，没有新改动。

2. **大图送模型前缩小后，会在结果里标明「缩过」**  
   以前只缩小不上报，调用方看不出图被压过。现在结果说明里会带上这条信息。

3. **下载失败时临时目录一定会删掉**  
   以前只有某几类错误会清，其它异常可能留下垃圾目录，跑久了占磁盘。

4. **Excel 只按「只读」方式打开**  
   读失败就降级说明，不再偷偷整本加载。畸形文件曾可能把内存打爆，这条路封掉了。

5. **压缩包 / 安装包列目录时立刻按上限截断**  
   仍报告真实总条数，但不再先建超长名单再砍。条目特别多的包更省内存。

6. **读残缺图片的开关收到单次打开里**  
   不再改成整个进程一直开着，避免影响同进程里别的读图逻辑。

7. **一键启动与前端开发服务读同一份端口配置**  
   改端口不用改两处；端口被占用会直接失败，不会悄悄换端口再把两边搞乱。

8. **前端小修**  
   表类型未知时按原值显示（不再一律显示成「数据表」）；空的样例标题会被拒绝；类型检查范围补上前端配置文件。

9. **EPUB / OFD / ODT·ODP 解压总量封顶**  
   以前容器成员整份 `read()` 进内存、无总量上限。现在一次请求共用 20MB 解压预算：读前看声明体积，再用流式封顶。必要条目超限整份降级；已有章节/页则截断后续并在结果里报 `max_zip_uncompressed_bytes`。原理与「资源防护公共件」这类模块怎么认，写进了管线说明第 4.1 节和术语表。

10. **上传请求体早拒补全**  
    以前中间件只认「声明有多大」；没声明时框架可能先把整包写进系统临时目录再拒。现在声明超限仍直接拒，没声明或边收边超也累计断开（413）。业务落盘那道上限保留。RUNBOOK 写了反代 `client_max_body_size` 怎么配。
