# 架构决策（现行）

仍有效的为什么。

## ADR-0001 · 2026-10-16 · 对外只留统一转换接口，扩展用能力开关叠加

曾经用两条 URL 区分「只抽文本」和「再调模型」，把对比本身做成产品身份。对外只留一条转换接口；OCR / ASR / LLM 是否上阵，由请求上的能力开关和扩展是否可用共同决定。消费方是 LLM 或工作流节点，需要稳定入口；原始文本和摘要才是产物，开不开扩展不是第二种产品。否掉双路对比和旧路由长期别名。

## ADR-0002 · 2026-10-16 · 交付文本与摘要分开放；转写仅在实际跑过时并入

调用方要把原始文本交给下游，摘要是另一份产物，二者不能互相覆盖。交付文本 = 规则抽出的确定性段 + 本次实际跑过的 OCR / ASR / 看图转写；摘要只由 LLM 在启用且可用时产出。失败也走同一套响应形状，避免调用方按成功失败换键。否掉「用摘要覆盖正文」和「模型字永远只进 meta」。

## ADR-0003 · 2026-10-16 · 覆盖以纯 Python 库能否做到划线；降级不是错误

纯 Python 库能解析的完整实现；做不到的不报错，返回基础文件信息并声明缺什么。图片和音视频在对应扩展未跑时也是这种正常结果，不是故障。否掉「不支持的类型直接报错」。

## ADR-0004 · 2026-10-16 · 扩展按能力→提供商注册；看图走 LLM，OCR 只做文字图单选

扩展既有本机独立服务也有第三方 API，「谁能干这件事」不能写死成一家。能力与提供商分开登记；看图（判型、描述、扫描页、内嵌图）只取决于 LLM；OCR 只决定独立文字图交给哪家提供商。否掉「OCR 打进核心必装依赖」和「只开一半看图开关仍强行半跑」。

## ADR-0005 · 2026-10-16 · 下载层四条安全基线不可为成功率放松

服务接受用户可控 URL，这四条必须同时成立：

1. 每次实际连接前核对解析出的每一个地址，命中私网 / 回环 / 保留等一律拒绝；解析与连接钉在同一 IP；禁止 https 降到 http。
2. 下载按累计字节封顶，超限中断并丢掉半成品。
3. TLS 证书问题直接失败，不关校验。
4. 请求体能早拒就早拒，否则边收边数，超限拒绝。

否掉任何为提高成功率而放松其中一条的改动。

## ADR-0006 · 2026-10-16 · 扫描件页面渲染必须有页数上限

无文字层的 PDF 要靠把页面画成图再交给视觉 / LLM，费用随页数线性涨。未启用相应扩展时只声明无文字层；启用后整页渲染，但页数必须有上限，超出的声明跳过。否掉「不设上限」和「每页固定切多张」。

## ADR-0007 · 2026-10-16 · 按流程步骤与一类格式一个文件分包；不设行数门禁

按技术分层或用行数上限逼拆文件，都会把同一格式拆碎、把调度和实现搅在一起。处理流程按步骤排；同一类格式收在一个处理器文件里；跨格式公共件按是否调用扩展分开。否掉空的 core 包、独立 contracts 包，以及用行数门禁逼出来的碎片文件。

## ADR-0008 · 2026-10-16 · 仓内不附托管脚手架

本仓默认本机开发、自用。公开仓只给说明，不附带容器、系统服务或完整反代样板；谁要对外面部署谁自己配。否掉「仓内做一套生产默认进程模型」。

## ADR-0009 · 2026-10-16 · 核心后端用 uv；扩展可自带环境

核心依赖需要可复现的锁文件；OCR / ASR 等扩展的重依赖不该污染这份环境。核心走仓库根的 uv 环境；扩展模块可自带独立环境。否掉「任意 conda / pip + requirements.txt 当核心唯一安装路径」。
